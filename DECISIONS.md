# Architecture Decision Register

## D-001 — Shared application shape
- **Date:** 2026-10-31
- **Status:** Team target baseline
- **Decision:** Prefer a modular monolith with explicit UI, API, domain-service, and persistence boundaries.
- **Rationale:** Four-person hackathon team, short delivery window, fewer deployment/debugging moving parts.
- **Constraint:** Official organizer requirements override this decision.

## D-002 — Supabase PostgreSQL
- **Date:** 2026-10-31
- **Status:** Confirmed by team lead as required database choice; actual project configuration still needs verification
- **Decision:** Use Supabase PostgreSQL as the one authoritative application database.
- **Related choice:** Use Supabase Auth for identity; backend verifies tokens and enforces application permissions.
- **Not yet verified:** project URL, schema, migrations, Auth providers, grants/RLS, environment names, and any existing data.
- **Rule:** Audit current project and repository before changing remote schema. Never commit real keys. Never expose service-role credentials to browser code.

## D-003 — Standard technology stack
- **Date:** 2026-10-31
- **Status:** Team target baseline
- **Decision:** React + TypeScript + Vite; Tailwind CSS + shadcn/ui; React Hook Form + Zod; TanStack Query; Python + FastAPI + Pydantic; Supabase PostgreSQL; Pytest and Vitest.
- **Alternatives rejected for this baseline:** independent frontend frameworks, a second database, multiple business APIs, microservices without a demonstrated need.
- **Reason:** Familiar, fast to build, typed UI contracts, explicit backend business logic, relational persistence.

## D-004 — Contract-first integration
- **Date:** 2026-10-31
- **Status:** Adopted
- **Decision:** Shared API paths and schemas are documented in `API_CONTRACTS.md`; database entities and migrations in `DATABASE_GUIDE.md`. Any breaking change requires agreement and updated tests/docs.

## D-005 — Billing idempotency
- **Date:** 2026-10-31
- **Status:** Required design rule
- **Decision:** A recurring invoice must be uniquely associated with a subscription and billing period, with database-enforced duplicate prevention and safe retries.

## D-006 — AI is not an authorization layer
- **Date:** 2026-10-31
- **Status:** Adopted
- **Decision:** AI calls only approved backend tools; each tool independently enforces the caller's permissions and record ownership. No arbitrary SQL generated by the model.

## D-007 — Final submission branch
- **Date:** 2026-10-31
- **Status:** Team intent; reconfirm official organizer instruction
- **Decision:** Keep individual feature branches for development and consolidate reviewed working code into the required final branch. Current team intent is `main`.
- **Rule:** Do not force-push, reset, or overwrite teammates' work.

## D-008 — Official Odoo requirement gate
