# Official Challenge and MVP Delivery Plan

**Status:** Awaiting official problem statement. The team must not invent a challenge domain, features, user groups, AI integrations or judging criteria.

## Record authoritative information

- Exact title, full statement and official source
- User, pain point and measurable goal
- Required capabilities, prohibited approaches and platform constraints
- Odoo requirements (if any), official database/API instructions
- Judging rubric, deadlines, demo video and submission instructions
- Team lead's confirmed choice and any outstanding assumptions

Separate confirmed rules from organizer-video reports and team assumptions.

## Select the smallest working MVP

1. Define one primary user and one valuable end-to-end workflow.
2. Write observable acceptance criteria for that workflow.
3. Split it into `Must`, `Should`, and `Could` items.
4. Give each Must one owner, dependency list, data/API contract and test.
5. Deliver the first vertical slice before adding optional integrations.
6. Cut scope early if testing and submission time are at risk.

## Definition of done

A completed Must is real code and data, observable to the intended user, tested sufficiently to demonstrate the core flow, integrated into the submission branch and honestly documented. A mock response or static JSON alone does not establish working persistence.

## Challenge-domain decisions

Only select AI, payments, education, IoT, Odoo integrations, or other specialized systems when the chosen official problem warrants them. Record permissions, privacy, reliability and fallback expectations.
